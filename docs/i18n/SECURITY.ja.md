# セキュリティ

## このソフトウェアがあなたのマシンで行うこと

`prove-it` は、あなたが開いているリポジトリの中にあるスクリプトを実行する。信頼していないリポジトリを開き、その `verify.sh` が実行可能であれば、エージェントがターンを終えるときにそのファイルが実行される。

この挙動は欠陥ではなく設計であり、そのリスクは、`npm install` を走らせたり `Makefile` のあるプロジェクトを開いたりするときに、あなたがすでに受け入れているものと同じだ。見慣れない `postinstall` スクリプトを読むのと同じように、見慣れない `verify.sh` は、それを含むリポジトリでエージェントに作業させる前に読むこと。

ゲートが走るのは、セッションが**その同じリポジトリ**のファイルを編集し、ワーキングツリーが汚れていて、実行可能な `verify.sh` がリポジトリのルートに存在するときだけだ。リポジトリをクローンして読むだけでは、決してこれは起動しない。あるリポジトリを編集しても、別のリポジトリの `verify.sh` が走ることは決してない。

## ディスクに書き込むもの

2つのマーカー。どちらも、モード `0700` で作られた非公開ディレクトリの中にある。`$XDG_STATE_HOME/prove-it/`、それが未設定なら `~/.local/state/prove-it/` だ。`PROVE_IT_STATE_DIR` で上書きできる。共有の `/tmp` には何も書かない。これらのファイル名はリポジトリのパスから導かれるので予測可能であり、誰でも書き込めるディレクトリにある予測可能な名前は、シンボリックリンクの標的になるからだ。

任意の台帳(`PROVE_IT_LEDGER=1`、**デフォルトはオフ**)は、検出された偽の完了ごとに1行の JSON を `~/.prove-it/ledger.jsonl` に追記する。これは `0700` ディレクトリの中に、モード `0600` で作られる。各行は次を保持する:

- エージェントが停止しようとする前の最後のメッセージ。300文字に切り詰められ、ローカルのトランスクリプトから取られるので、あなたの会話にあったものは何でも含みうる
- リポジトリの絶対パス
- 終了コードと、`verify.sh` 出力の最後の5行
- タイムスタンプ

これは会話データとして扱うこと。このプロジェクトの何も、それを読み返したり、どこかに送ったりはしない。だがそれはふつうのファイルのままなので、バックアップはそれをコピーするし、あなたのホームディレクトリへの読み取りアクセスを持つ者は誰でも開ける。

## 送信するもの

何も送らない。あなたのマシンで走るソフトウェアには、テレメトリも、ネットワーク呼び出しも、更新チェックも無い。`hooks/` と `scripts/` 全体に対して `curl`、`wget`、`urllib`、`requests`、`socket` を1回 grep すれば、これを確かめられる。

継続的インテグレーションが唯一の例外だが、それはあなたが走らせるコードではない。GitHub Actions のワークフローは、あなたがローカルで走らせるのと同じ `verify.sh` を走らせる前に、`apt` または `brew` から `shellcheck` をインストールする。

## 脆弱性の報告

詳細と再現手順を添えて **hello@whynext.app** にメールしてほしい。上で述べた境界からリポジトリが抜け出せてしまうようなものについては、公開の issue を開かないでほしい。

数日以内に受領の返事があると思ってほしい。これは1人で保守しているので、辛抱してもらえると助かるし、再現手順も助けになる。私が再現できない報告は、私が直せない報告だ。

## サポート対象のバージョン

最新のリリース。このプロジェクトは十分に小さいので、バックポートは誰の得にもならないサービスだ。

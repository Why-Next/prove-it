# Support

`prove-it` is maintained by one small team. The fastest path to help is a
reproduction that starts from a fresh `git init` repository.

## Bugs

Open a bug report with:

- the smallest command sequence that reproduces the behavior
- the `verify.sh` involved
- the full gate output and exit code
- `bash --version | head -1; git --version; python3 --version; uname -sr`

If the report is about the convention rather than the implementation, use the
spec proposal template.

## Security

Do not open a public issue for a vulnerability. Email `hello@whynext.app`.
`SECURITY.md` describes what this project does on disk and what it does not
try to protect against.

## General questions

Use GitHub Discussions for open-ended questions and ideas. Use GitHub issues
only when the answer should become part of the public project history or when
the report can change the code or the docs.

Installation help without a reproduction may be redirected to the README or
Discussions, because issue triage needs to stay focused on problems that can be
reproduced.
